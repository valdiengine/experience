# SCAFFOLDING-STANDARDS.md — Code Generation Standards

## Overview

All code generated by the Valdi SDK must automatically comply with Engineering Standards, Architectural Invariants, and the Capability Contract. This document defines the standards for generated code.

## Generated Code Rules

### Rule 1: Zero Manual Configuration
Generated code must work immediately without manual edits. Every file must be complete, valid, and standards-compliant.

### Rule 2: Consistent Patterns
All generated capabilities follow the same pattern. All generated providers follow the same pattern. All generated managers follow the same pattern.

### Rule 3: Future-Proof
Generated code must be easy to extend. Use clear extension points. Avoid tight coupling.

### Rule 4: Documentation by Default
Every generated component includes README.md with purpose, dependencies, events, and usage examples.

## Capability Template

When `valdi create capability <name>` is executed, generate:

### File Structure
```
capabilities/{name}/
  {name}.capability.js     # Main capability class
  {name}.schema.js         # Entity schemas (if entities)
  {name}.events.js         # Event definitions
  {name}.manager.js        # Primary manager
  README.md                # Documentation
  __tests__/
    {name}.test.js         # Unit tests
```

### capability.js Template
```javascript
import { BaseCapability } from '../core/base.capability.js';

export class {Name}Capability extends BaseCapability {
  static id = '{name}';
  static name = '{Name}';
  static version = '1.0.0';
  static dependencies = [{dependencies}];

  #manager = null;

  async init(context) {
    await super.init(context);
    this.#manager = new {Name}Manager(context);
  }

  async activate() {
    await super.activate();
    this.#setupEventListeners();
  }

  async deactivate() {
    this.#removeEventListeners();
    this.#manager = null;
    await super.deactivate();
  }

  async destroy() {
    this.#manager = null;
    await super.destroy();
  }

  #setupEventListeners() {
    // Event listeners registered here
  }

  #removeEventListeners() {
    // Event listeners removed here
  }

  get manager() { return this.#manager; }
}

export default {Name}Capability;
```

### manager.js Template
```javascript
export class {Name}Manager {
  #context;
  #data = new Map();

  constructor(context) {
    this.#context = context;
  }

  // Add methods here

  destroy() {
    this.#data.clear();
    this.#data = null;
    this.#context = null;
  }
}
```

## Provider Template

When `valdi create provider <name>` is executed:

### File Structure
```
providers/{name}/
  {name}.provider.js     # Provider implementation
  {name}.config.js       # Configuration schema
  README.md              # Documentation
```

### provider.js Template
```javascript
import { BaseProvider } from '../base.provider.js';

export class {Name}Provider extends BaseProvider {
  #config;
  #initialized = false;

  constructor(config) {
    super();
    this.#config = config;
  }

  async load() {
    // Initialize connection
    this.#initialized = true;
  }

  async get(path) {
    // Read value at path
  }

  async set(path, value) {
    // Write value at path
  }

  async remove(path) {
    // Delete value at path
  }

  async getAll() {
    // Return all data
  }

  async refresh() {
    // Reload from source
  }

  get meta() {
    return {
      type: '{type}',
      initialized: this.#initialized,
      hasData: this.#data !== null
    };
  }
}
```

## Manager Template

When `valdi create manager <name>` is executed:

### File Structure
```
managers/{name}/
  {name}.manager.js      # Manager implementation
  README.md              # Documentation
```

### Manager Design Rules
- Single responsibility
- Private internal state (#field)
- Public methods only for business operations
- destroy() must clean up all resources
- Maximum 300 lines (split if larger)

## Event Naming Standards

Generated events must follow:
```
domain:entity.action
```

Examples:
- `booking:created`
- `reservation:confirmed`
- `ecology:observation.created`

Rules:
- Lowercase domain
- Lowercase entity
- Past tense action
- Colon separator
- Dot for sub-entity

---

## Version Standards

- All generated components start at version 1.0.0
- Use semver format (MAJOR.MINOR.PATCH)
- Version must be declared in static property

---

## Import Standards

Generated code must:
- Import from shared/ for utilities
- Never import from higher layers
- Never import from sibling capabilities
- Use context.capabilities.get() for cross-capability access
- Use this.on()/this.off() for event listeners
