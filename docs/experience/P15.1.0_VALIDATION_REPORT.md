## 2. Target Architecture

Per P15.0 and the Platform Manifest, the target architecture after P15.1 is:

```
PLATFORM CORE (v4.0 — Certified)
        │
        ▼
PRODUCT RESOLVER          ← NEW (P15.1.1)
        │
        ▼
ECOSYSTEM LOADER           ← NEW (P15.1.1)
        │
        ▼
EXPERIENCE ENGINE          ← NEW (P15.1.1)
        │
        ▼
MODULES → CAPABILITIES → PLATFORM CORE
```

### 2.1 Experience Engine Responsibilities (Target)

From PLATFORM_MANIFEST.md Section 3.3:

- **Composition**: Products, Modules, Capabilities, Navigation, Branding, Layouts, Workflows, Permissions, SEO, Localization, User Journeys
- **Configuration**: Declarative composition, no business logic
- **Orchestration**: Assembly of pre-existing capabilities

### 2.2 Experience Engine MUST NOT Do

- Business persistence
- Database access
- Authentication persistence
- Payment processing
- Storage provider implementation
- Filesystem access
- Cloud SDK access
- Business rules belonging to BusinessService

## 15. Product Independence Demonstration

### How Dronestica and Tourism Products Coexist

**Current State:**
- Dronestica-specific config in `config/product.config.js`
- Dronestica product data in `data.js`
- Engine UI reads from `window.DATA` via `PRODUCT_CONFIG`

**Target State (After P15.1):**
- Dronestica becomes `ecosystems/cl/regions/los-rios/destinations/valdi/`
- Dronestica company becomes `companies/cl/los-rios/valdi/dronestica/`
- Experience Engine loads correct config based on domain
- Engine UI receives dynamically composed data

**Key Principle:**
Dronestica values remain in configuration/data boundaries, never in Platform Core.

## 16. Multi-Ecosystem Readiness

### How Multiple Destinations Use Same Engine

```
valdi.app        → Experience Engine → valdi destination config
natales.app      → Experience Engine → natales destination config
puntaarenas.app  → Experience Engine → puntaarenas destination config
chiloe.app       → Experience Engine → chiloe destination config
coyhaique.app    → Experience Engine → coyhaique destination config
```

Each destination is a separate configuration set. The Experience Engine:
1. Resolves the domain to an ecosystem context
2. Loads the hierarchical configuration
3. Composes the experience from capabilities
4. Renders the product-specific UI

**No engine modification required for new destinations.**
