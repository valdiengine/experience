# Knowledge Domain

> Why the platform exists. This folder describes ideas, never implementation.

## Contents

| File | Purpose | Audience |
|------|---------|----------|
| `WHY.md` | Why this platform exists. What it is NOT. | Everyone |
| `PLATFORM_MANIFESTO.md` | Visionary declaration of purpose | Governments, Investors, Partners |
| `DESIGN_PRINCIPLES.md` | 14 immutable design principles | Developers, Architects |
| `VISION_EVOLUTION.md` | 16-stage evolution from directory to ecosystem | Everyone |
| `FUTURE_IDEAS.md` | Organized future concepts across 9 categories | Product, Research |
| `PLATFORM_GLOSSARY.md` | Official vocabulary with single definitions | Everyone |
| `AI_GUIDELINES.md` | Instructions for AI systems | AI agents |
| `ARCHITECT_DECISIONS.md` | 15 architectural decisions with rationale | Architects, Developers |
| `PROJECT_EVOLUTION.md` | Historical narrative of platform evolution | Everyone |

## How to Use This Folder

- **New team member?** Start with `WHY.md` and `PROJECT_EVOLUTION.md`
- **Developing a feature?** Read `DESIGN_PRINCIPLES.md` first
- **Architecture decision?** Read `ARCHITECT_DECISIONS.md` first
- **Planning roadmap?** Check `FUTURE_IDEAS.md` for possibilities
- **Writing docs?** Use `PLATFORM_GLOSSARY.md` for terminology
- **AI agent?** Read `AI_GUIDELINES.md` before any work

## Relationship to Other Folders

- `docs/ai/` — Current implementation state (changes frequently)
- `docs/architecture/` — How the platform works (technical)
- `docs/api/` — Communication contracts (reference)
- `docs/roadmap/` — Where development is going (planning)
- `docs/vision/` — Where the platform could evolve (inspiration)

This folder is **intentionally non-technical**. It describes beliefs, principles, and possibilities — not code.
